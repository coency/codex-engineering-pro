# 安全实现

## 修改前

先读取[共用工作约定](../../references/mode-b.md)。核对用户目标、授权范围、现有改动和适用的项目约定；读取相关实现、调用方和现有测试。不要假定未提交文件都是本次生成的。

目标不足以决定正确行为时，先补调查或按需读取[需求规划](../cep-requirement-planner/SKILL.md)。目标清晰的小修复无需长计划。

## 修改时

沿用项目现有抽象、依赖和命名，优先修根因，控制必要改动范围。不要顺手大改格式、升级无关依赖或删除看似无用的代码。

检查输入边界、异常处理、资源释放、并发和兼容性中与任务实际相关的部分。不要把错误吞掉、跳过鉴权、写死凭据或用关闭测试来掩盖缺陷。

对用户已有修改进行精确合并；若同一区域的意图无法判定，保留现场并问清楚。执行依赖安装、迁移、清理和脚本前检查其真实副作用。危险动作必须单独核对授权。

## 修改后

查看最终差异，确认没有意外文件、秘密、生成物或范围外修改。按需读取[测试验证](../cep-test-verification/SKILL.md)，运行与行为相称的检查。对无行为变化的低影响调整不机械增写测试。

复杂改动或用户要求审查时，交给[独立代码审查](../cep-independent-code-review/SKILL.md)的单独审查阶段。按实际发现迭代，不凭“应该能用”宣布成功。

交付行为变化、涉及位置、验证结果和未覆盖风险。不把本地可回退修改的授权扩张为提交、推送、发布或生产操作。
