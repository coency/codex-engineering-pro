# 代码库调查

## 调查边界

先读取[共用工作约定](../../references/mode-b.md)。默认只读；不要通过安装依赖、运行未知构建脚本或改配置来完成“调查”。用户另有修改授权时，也先交付调查结果，再进入已授权的实现阶段。

从用户关心的功能、错误或边界出发。优先查项目说明、清单、目录结构和适用约定，使用精确搜索定位入口、符号和引用；不要无目的遍历所有文件或输出秘密。

## 形成可核查的解释

1. 确定语言、构建入口、包管理工具、服务或应用边界，并从实际文件取证。
2. 沿用户问题追踪输入、核心处理、存储或外部调用、输出。读调用方与被调用方，避免只凭文件名判断职责。
3. 找出相关配置默认值、异常分支、兼容要求、测试位置和现有运行命令；命令仅从仓库取证，未经执行标记为建议。
4. 区分代码事实、合理推断和待确认事项。动态行为无法从静态代码证明时，说明还需要什么运行证据。
5. 停在足以回答问题或支持下一步的位置，避免把调查扩大为全仓库审计。

## 输出

给出简短模块地图或调用链，以及带路径和行号的关键证据、可用验证入口、潜在影响范围和未确定项。用户只问解释时，到此结束。
